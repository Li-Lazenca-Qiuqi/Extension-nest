# Demo 结构

- `src/`：真实 VS Code 扩展宿主、原生 TreeView、Webview 消息桥。
- `demo/src/`：编辑器 Dashboard 的 React 界面及纯状态模型，不包含网页侧边栏。
- `demo/src/Sidebar.tsx`：仅保留聚焦原生分组视图的消息辅助函数，不渲染任何 UI。
- `demo/src/state.test.ts`：状态约束测试。
- `doc/design/dashboard-editor-concept.png`：无侧边栏的当前 Dashboard 视觉参考。
- `doc/design/dashboard-concept.png`：被用户否定的初始网页侧边栏参考，不是实现依据。

## 视觉约定

深色背景 #17191d，面板 #202329，边界 #303640，薄荷色 #a0dfb8。字体跟随 VS Code，浏览器验证回退 Segoe UI。表格为核心，不使用卡片替代插件列表。禁用灰显，管理操作标明示例数据。

当前设计沿用新参考的标题、统计带、列表、筛选、按钮和底部提示。根据用户纠正，侧边栏只能使用 VS Code 原生树；不再单独交付网页应用。浏览器入口仅用于组件开发检查。

## 数据与安全边界

DemoState 是演示全快照，包含示例扩展和分组，不等于正式 PRD 的 assignments 交换格式。运行宿主通过 globalState 持久化示例快照；管理操作不调用真实插件安装/卸载命令。

所有消息经宿主校验。Dashboard 的本地预览分支不能访问用户真实扩展。正式 M0 目标没有因 Demo 完成而自动完成。

## 本轮验证

已通过扩展宿主 TypeScript 检查、Dashboard 构建、11 项单元测试（含原生拖放控制器到唯一归属服务的处理路径）。在本机 VS Code 1.137.0 的真实 Extension Development Host 中观察到：原生组点击筛选编辑器 Dashboard；Python 禁用后两处显示 Disabled，Enabled 从 11 变为 10、Disabled 从 3 变为 4；鼠标把 Python 移到 Writing 后原生计数从 4/2 变为 3/3。

自动化鼠标拖动没有触发 Electron TreeView 的 handleDrag/handleDrop，因此不声称真实拖动手势已通过。控制器逻辑测试通过，鼠标移组入口已验证；真实拖动仍需用户在开发窗口试用。导入导出与卸载有实现和状态测试，但本轮未逐项完成原生文件对话框端到端测试。

视觉对照使用无侧边栏参考；原生编辑器实际宽度随用户布局变化，不能按独立 1536×1024 网页要求等尺寸。已核对无重复侧边栏、深色与薄荷色配色、标题层级、统计带、表格与按钮排列，并修复窄编辑器下管理按钮横向溢出。示例版本号采用固定测试数据，与概念图数值有意不同；不将它们当成真实 Marketplace 最新版本。

原生宿主检查没有信任工作区或更改任何安全设置。Demo 在当前受限模式窗口中已显示并完成上述交互。
