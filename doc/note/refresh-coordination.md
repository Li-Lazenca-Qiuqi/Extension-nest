# 刷新协调与宿主生命周期

2026-09-19：`RefreshCoordinator` 统一启动、事件、手动和 Dashboard 返回入口。事件采用 150 ms 去抖，手动请求可提前执行；进入写队列前的请求合并。扫描中出现新请求会递增请求代次，旧扫描不再发布，结束后将一次补读放回写队列尾部，避免越过已排队的组织保存。调用者等待补读完成，而非仅等待失效扫描结束。

组织保存、清理和扫描共用宿主串行队列。释放会取消定时器、使请求代次失效、停止新写入及界面通知，并等待已入队工作结束后释放单写者锁。已发出的 `globalState.update` 不可撤销；失效检测禁止后续发布，不承诺回滚已提交写入。

Dashboard 只在重新可见或重新激活时请求刷新，失去焦点且仍可见不再额外请求。刷新发布不触发刷新入口。

## Profile 身份边界

本机 VS Code 构建 `7debcd0e2acdea1c52de81bf9ee1620444407dda` 的 Workbench 产物中，`changeCurrentProfile` 在 Profile ID 或资源继承选项变化时：

- 无 Remote 连接：先等待 `stopExtensionHosts`，再更新 Profile，随后 `startExtensionHosts`；停止被否决则撤销切换。
- 有 Remote 连接：更新 Profile 后提示窗口重载，确认才调用 `hostService.reload`。

因此本地宿主重建可作为上下文边界；请求代次仅代表本宿主内的刷新请求，绝不冒充原生 Profile ID。切回 Profile 创建的新宿主不会复用旧协调器。本机源码核验之外，用户随后对给出的真实宿主检查清单反馈“全部没问题”，据此记录 GAP-05 用户验收通过。清单包含连续刷新、切回 Dashboard、整理后刷新/重载、Profile 切换/切回及可选 Remote 重载检查；未提供分项日志、Remote 类型或重载分支细节，因此不把这次反馈当作完整 Remote 环境认证，也不宣称已取得实时 Profile 身份。
