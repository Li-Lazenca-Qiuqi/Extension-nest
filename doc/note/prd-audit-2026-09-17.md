## 确认的实现缺口（7 项）

### GAP-01：默认 Visible 隐藏空组及拖放入口

`demo/src/App.tsx:17,53` 默认 Visible 导致 filtered=true；`demo/src/groupExtensions.ts:9` 删除无匹配条目的分区。保存过的空组在重新打开面板时没有标题/落点，违背 PRD-006/011/016。只有历史记录的组在此筛选下也无落点。

本轮直接调用实际纯函数：传入一个空组、空记录、all、filtered=true，返回 `[]`。应保留默认视图的空组和 Ungrouped 落点；搜索筛选规则可另行明确，不能通过恢复默认 All 绕过用户决定。

### GAP-02：Ungrouped 与可见性条件无法同时选择

`demo/src/App.tsx:43,46`：选 Ungrouped 会清掉可见性，选 Visible/Not found 又清掉 Group。底层交集算法正确，但用户无法构造 Ungrouped ∩ Not found（或 Visible）。应保留 Group 与可见性独立组合，All 仍清空全部条件。涉及 PRD-003/017。

### GAP-03：新发现条目没有默认名称/ID 排序

`src/discoveryState.ts:62` 按已保存顺序和对象键插入顺序合并；没有对无保存顺序的新项排序。本轮以 Zulu、Alpha 顺序传入真实 observe/projectDiscovery 函数，输出仍为 Zulu、Alpha。PRD-007 要求新项按名称、同名按 ID 稳定排序；修复时不能重排已有用户顺序。

### GAP-04：损坏组织数据与缓存没有修复入口

`src/discoveryRepository.ts:19–62,115–117` 已严格拒绝坏数据、保留原值并进入错误/只读状态；Refresh 只能重读同一坏值。PRD-009 要求的专门恢复交互尚未实现，应区分组织数据和发现缓存，保护另一份有效数据；涉及丢弃数据的修复必须明确范围并确认。Clear old records 仅清理有效状态中的旧占位，不能替代损坏恢复，也不应为该清理增加备份。

### GAP-05：同步缺上下文代次/请求控制，触发源未统一合并

`src/extension.ts:303–304,354–383` 有队列、150 ms 事件去抖和 disposed 检查；`src/dashboardPanel.ts:64,122` 面板可见和手动刷新直接调用 refresh。没有 PRD-015 指定的上下文 generation / 请求序号，队列不能代替过期请求丢弃，所有触发源也尚未统一合并。应在稳定 API 范围内实现或用实测证明宿主生命周期提供等价隔离，覆盖切 Profile/切回和异步保存期间释放；不能伪造实时 Profile ID。本审查未证明已发生跨 Profile 污染。

### GAP-06：空状态未充分区分历史、筛选及失败

`demo/src/App.tsx:51–52` 在存在已知记录但 rows 为空时统一提示 No matching extensions；默认 Visible 下只有历史项也进入该分支，无法直接说明“本次未发现，但有保留记录”。该分支还先于 Error/Stale 判断。页脚仍有错误标志，不等于完全没有错误反馈；缺的是 PRD-001/011/016 要求的明确空状态及相应查看历史/重试入口。

### GAP-07：最近成功扫描时间未展示

`src/discoveryRepository.ts:58` 保存 lastSuccessfulAt，模型也有该字段；`demo/src/App.tsx:55` 只展示 Local host、新鲜度和保存状态，没有成功扫描时间。PRD-016 要求的时间/缓存时间反馈尚缺；Stale 时应保留上次成功时间，不能用失败时间替换。
