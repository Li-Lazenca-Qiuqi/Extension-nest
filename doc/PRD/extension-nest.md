# Extension Nest 产品需求文档

更新日期：2026-09-12

状态：需求设计，已纳入用户本轮明确修改；尚未实现或发布。

工作名称：Extension Nest；正式名称、publisher 和 License 待确认。

## 1. 来源与当前基线

起点为用户指定的[“vscode插件分组方法”聊天](https://chatgpt.com/c/6a3e8b9a-2fa8-83ee-9434-b25eb36b0ec2)。当前以用户本轮指示为准：**单一分组、鼠标为主且支持拖拽、复用原生扩展管理、全部已安装扩展可见、禁用灰显、提供 Dashboard**。

这六项取代初稿的多组归属、拖拽复制、管理功能后置和仅展示可检测集合等规则。实现细节属于本稿建议，证据和取舍见[当前决策](../decisions/002-single-group-management-dashboard.md)。本次仅修改文档，不制作可运行 Dashboard 或执行安装、启停、卸载。

## 2. 产品目标

帮助安装大量扩展的 VS Code 用户以鼠标整理和管理插件：打开分组或 Dashboard，找到扩展，拖动分类，直接进入启用、禁用、更新或卸载流程。无需为了整理插件切换 Profile。

### 成功标准

- 每个 Extension ID 至多属于一个自定义组；未分配的插件位于 Ungrouped。
- 拖入新组即移动；原组不再保留该插件。分组和启停互相独立。
- 当前管理范围内，所有已安装扩展都可查看，包括禁用、未激活及本地 VSIX 扩展，不因元数据 API 缺失而静默漏项。
- 与 VS Code 原生扩展管理保持同一真实状态；操作完成后分组页与 Dashboard 同步。
- 鼠标点击、拖动、右键和可见按钮可完成核心流程；无需记忆快捷键或输入命令。
- Dashboard 可看、可筛选、可操作，首版交付时不是静态示例。

## 3. 范围与概念

| 概念 | 定义 |
| --- | --- |
| Extension ID | 规范化的 publisher.name；分组以此为主键，不使用显示名 |
| Group | 一级自定义文件夹式分组；无嵌套；每个 ID 至多一个归属 |
| Ungrouped | 未分配自定义组的插件，是唯一归属的默认位置 |
| 安装实例 | 同一 ID 在某个安装目标的实例；版本和启用状态可能随 Local、WSL、SSH 等环境不同 |
| 当前管理范围 | 当前 VS Code Profile 对应的本地安装，以及当前窗口已连接的 Remote 安装；不自动连接未连接服务器或枚举其他 Profile |
| 全量列表/状态筛选 | All Installed、Enabled、Disabled、Updates 等查询视图，不保存分组归属，不构成第二个自定义组 |
| 保存的分组关系 | 已确认卸载或暂时离线后仍可保留的单组元数据，供重装/重新连接恢复 |

### P0：首版必须交付

完整安装清单；原生侧边栏分组；单组分配；插件拖动移动和组拖动排序；鼠标批量选择；创建/重命名/删除组；移至 Ungrouped；真实启用状态及禁用灰显；启用/禁用（全局或 Workspace）、更新、卸载；原生详情入口；状态同步；本地保存；JSON 导入导出；Dashboard 的统计、列表、搜索、筛选和操作。

### P1/P2：后续范围

- P1：收藏、自定义图标、导入合并、Settings Sync、批量启停和批量卸载、自选其他 Profile/未连接 Remote 管理。
- P2：规则分类、Smart Groups、AI 分类、Extension Pack/工作区推荐生成、使用统计和未使用检测。分类建议接受后也只能产生唯一归属。

### 非目标

不自建 Marketplace、不自己下载更新包或解析依赖、不修改 VS Code 私有数据库、不自动改 Profile 或自动更新设置、不提供云账号。分组数据本地保存；Marketplace 查询与管理按原生流程使用网络。不把项目自身账号或遥测作为使用前提。

## 4. 界面与鼠标交互

### 4.1 两个入口，共用同一份状态

- **侧边栏**：Activity Bar 中的 Extension Nest，原生 TreeView 显示自定义组和 Ungrouped；扩展在分组树中只显示一次。
- **Dashboard**：点击侧边栏标题上的 Open Dashboard，在编辑器区域打开独立面板；已有面板再次点击时聚焦，不创建多个互相失步的实例。用户明确要求直接接入 VS Code，不得在 Webview 中再制作网页侧边栏或模拟 VS Code 外壳。
- 侧边栏不额外挂一个重复的 All Installed 分组树；全量清单和状态查询集中到 Dashboard，避免看起来同一插件属于多个组。

### 4.2 鼠标优先

| 位置/动作 | 交互 |
| --- | --- |
| 组标题 | 点击展开/折叠；右键重命名、删除、导出和添加扩展；拖动标题排序 |
| 扩展行 | 点击选中；可见详情按钮或右键打开原生详情；右键提供 Move to Group、Move to Ungrouped、Enable/Disable、Update、Uninstall、Copy ID |
| 插件拖放 | 从当前组拖到目标组即移动；拖到 Ungrouped 即解除归属；悬停提示 Move to… 并突出目标 |
| 批量整理 | Dashboard 行复选框支持纯鼠标多选，拖动选中集合或点击 Move to Group；TreeView 可保留系统多选辅助 |
| 标题工具栏 | Create Group、Refresh、Open Dashboard；其他动作置于可点击更多菜单 |
| 名称/搜索输入 | 输入文本仍可使用键盘，但不要求快捷键、命令面板或 Shell 命令 |

“键盘操作”仅指可选的 Tab 切换焦点、方向键浏览、Enter 确认和快捷菜单等辅助访问，不是主要工作流。保留基础可访问性，不以键盘路径替代鼠标入口。

### 4.3 唯一归属与拖动规则

从 A 拖入 B，单次提交把归属从 A 改为 B；A 数量减少，B 增加。重复拖入当前组不改变数据。批量分配会移动已归类的扩展，确认界面说明受影响数量；普通拖动本身就是明确移动，不再追加确认。

将插件拖到 Ungrouped 清除归属。拖到空白、扩展叶子或不支持的外部载荷不写状态。拖动组只改变组顺序，不创建嵌套组。根据用户要求，分组拖放在真实 VS Code TreeView 内完成；Dashboard 提供行内和批量移动入口，不复制侧边栏或依赖跨面板拖放。

### 4.4 状态表达

- Enabled：正常主题前景色；Disabled：灰色/降低视觉强调，同时显示 Disabled 文本或标记，仍可点击、拖动和管理。
- Workspace 禁用与全局禁用在 Tooltip 或状态详情区明确标注；因信任、策略、依赖或环境而不可用时显示原生原因，不能冒充用户禁用。
- 未激活不等于禁用。读取失败显示 Unknown；待重启显示 Restart Required，不伪装为已经生效。
- 同一 ID 存在不同环境实例时，组内仍只有一行，状态可显示 Mixed；展开实例选择或在 Dashboard 切换安装目标后查看准确状态。混合状态不整行当成 Disabled。
- Dashboard 确保禁用行灰显；原生树的着色方式在 M0 验证，不假定 TreeItem 可任意设置 CSS。若完整行着色不支持，采用主题支持的灰色图标/说明文字及 Disabled 标记，保留可读性。

## 5. Dashboard 产品定义

Dashboard 是 P0 的正式管理面板，默认展示当前管理范围内所有已安装扩展。界面保持简洁紧凑，不使用宣传式标题、副标题或大面积留白；统计为单行紧凑筛选，插件采用卡片网格。以下布局是需求说明，不是已生成的 UI 原型。

| 区域 | 内容与行为 |
| --- | --- |
| 顶栏 | 当前 Profile/安装目标，Refresh、Check Updates、打开原生 Extensions 入口，数据更新时间 |
| 概览 | Installed、Enabled、Disabled、Updates、Ungrouped；点击卡片应用对应筛选 |
| 分组入口 | 导航和拖动放在 VS Code 原生侧边栏；Dashboard 仅用工具栏组筛选器和行内移动入口，不另占侧边栏 |
| 插件卡片网格 | 每个插件一张紧凑卡片，显示图标、名称、publisher、版本、唯一分组和启用状态；保留复选框、更新及管理按钮。自适应列数，不使用表格列表 |
| 搜索/筛选 | 按名称、ID、publisher 搜索；按分组、状态、安装目标、Built-in/User Installed 类型筛选；Clear Filters 一键恢复完整清单，默认不排除内置扩展 |
| 反馈区 | 加载中、同步失败、操作进度、重启要求、离线与重试；不显示虚构统计或成功状态 |

计数口径必须可解释：Dashboard 的 Installed 等管理统计按当前筛选安装范围的**安装实例**计数，界面说明 Includes local and remote installations；组内数量按唯一 Extension ID 计数。默认聚合列表每个 ID 一行，展开可看实例；跨环境相同 ID 不被误当成两份分组。选择单一目标后统计和列表均限定该目标。

Enabled、Disabled、Unknown 构成安装实例的互斥状态分类；受策略阻止而非正常启用的实例在 Disabled 详情标明原因。Updates 是可与任意启用状态交叉的子集，未知更新状态单独提示。Ungrouped 统计未分组 ID 对应的安装实例，不能拿组数相加去伪造实例总数。

没有数据时区分“尚未读取”“读取失败”“已确认没有安装”和“筛选无结果”。禁用条目默认不隐藏。仅颜色不应承担唯一状态信息；Light、Dark、High Contrast 下均可读。

## 6. 功能要求

| 编号 | 功能 | 必须满足的行为 |
| --- | --- | --- |
| F01 | 全量安装清单 | 对当前管理范围建立完整已安装清单，与原生安装清单逐 ID/目标比对；包含禁用、未激活、VSIX、无 Marketplace 条目的安装；内置扩展提供独立可选过滤但不遗漏；缺少元数据时仍以 ID 占位 |
| F02 | 分组树 | 自定义组与 Ungrouped 互斥覆盖全部已安装 ID；一个 ID 一行；支持原生展开折叠并尽量保留刷新前位置 |
| F03 | 全量/状态视图 | All Installed、Enabled、Disabled、Updates 及 Built-in/User Installed 为 Dashboard 筛选；没有额外归属；计数遵循第 5 节 |
| F04 | Group 管理 | 创建/重命名/确认删除；稳定 ID；删除组使成员回到 Ungrouped，绝不顺带卸载插件 |
| F05 | 单组分配 | 批量选择和菜单分配到唯一目标；已有归属被替换；可解除归属；不能保存多个组 ID |
| F06 | 插件拖动 | 拖入目标组即移动、拖入 Ungrouped 即移出；批量移动一次写入；失败恢复原分组，不留下重复或半完成关系 |
| F07 | 组排序 | 鼠标拖动排序并持久化，另保留 Move Up/Down；Ungrouped 固定；组内默认名称排序，同名用 ID 稳定排序 |
| F08 | 原生详情 | 打开对应 ID 的原生详情/管理页；复制完整 ID；调用失败说明原因并提供可点击原生查找入口 |
| F09 | 本地状态 | 保存唯一分组和顺序；读取损坏或写入失败不以空状态覆盖；重启和普通 Workspace 切换不丢分组 |
| F10 | 导入导出 | UTF-8 JSON；全量及单组导出；完整校验、预览和确认替换；拒绝多归属冲突，保留尚未安装 ID 的唯一归属 |
| F11 | 首次引导 | 无组时引导 Create Group 和鼠标选择插件；取消保留空组；所有核心命令有可点击入口 |
| F12 | 启用/禁用 | 复用原生流程，支持原生允许的全局/Workspace 范围；明确安装目标；禁用后条目留在原组并灰显，重启要求由原生流程处理 |
| F13 | 更新 | 提供检查更新、单插件更新及打开原生更新列表；显示已装/可用版本；遵守原生渠道、兼容性与更新设置，不自建下载机制 |
| F14 | 卸载 | 在原生确认流程中核对名称和目标；成功后相应安装实例消失；仍有其他实例则保留插件行；单组元数据保留供重装恢复 |
| F15 | 同步 | 在原生界面外部完成安装/启停/更新/卸载后，两种界面均同步；操作后重新读取真实状态，不只根据点击结果改图标 |
| F16 | Dashboard | 按第 5 节交付真实统计、鼠标筛选、搜索、分组移动和管理入口；共享服务与状态，不能各自保存一套分组 |

### 6.1 名称与删除

组名 trim 后非空、最长 50 个 Unicode 字符，按大小写不敏感去重；Ungrouped 为保留名称。改名不改变 ID。取消对话框不改状态；特殊字符按纯文本处理。

删除组确认只针对组织元数据，说明不会卸载扩展；组及其保存的归属一并移除，已安装成员进入 Ungrouped。

### 6.2 完整性和范围

“全部已安装可见”是验收要求，不能以 vscode.extensions.all 的返回值重新定义。原生 Marketplace 中没有条目、图标或描述时，已安装记录仍显示 ID 和可用信息。禁用不能成为隐藏理由。

当前 Profile、Local 与已连接 Remote 的默认范围是本稿工作解释；不自动连接其他主机。按同一范围与原生清单对照，原生内置扩展也须在明确过滤入口中可查看。切换 Profile 后重新读取该 Profile 的安装集，不混入旧目标；分类持久化的隔离策略在 M0 记录。

本稿所有“完整/全部”及验收数据均以上述当前管理范围为边界，而非所有设备和所有 Profile 的并集。Dashboard 持续显示此范围，验收记录同时写明 Profile 和连接目标；在这个范围内不允许漏掉任何已安装实例。

连接中断或同步失败保留上次清单并标记 Stale/Offline，不清空为“已卸载”，不显示“同步完成”。初次读取不完整时提示清单不完整并给重试入口；未补齐前不能判定 F01 完成。

## 7. 原生 Marketplace/扩展管理集成

“与 Marketplace 同步”在本产品中包含：跟随 VS Code 已安装列表与启用状态、读取原生更新结果、从本插件发起原生管理操作，并同步用户在原生界面进行的修改。不是把本地分组上传到 Marketplace，也不是重新实现市场。

### 7.1 调用原则

优先公开命令和可支持的 VS Code 原生接口，统一经 ExtensionManagementAdapter 调用。直接调用不具备稳定能力时，提供明确标识的 Open in VS Code 操作，定位到目标扩展，由用户在原生界面完成；不能把“跳到详情页”记录成“已禁用/已更新”。

原生操作必须最终能完成用户需要的管理流程；清单与真实状态读取仍需独立满足 F01/F15。若无可维护途径完成，记录技术阻塞并回报，不静默把功能降级到 P1。

不读取或修改 VS Code 私有数据库来强制状态；不复制依赖解析、下载或安装器。不随意使用当前 Shell 中的 code 命令，因为它可能指向错误版本、Profile 或宿主。CLI 仅作为经过目标校验的原生补充方案。

### 7.2 操作反馈

1. 确定 Extension ID、安装目标及操作范围；有多个实例时先以鼠标选择目标。
2. 根据真实能力展示 Enable/Disable、Update 或 Uninstall；未知状态允许重新同步或进入原生管理，不猜测。
3. 调用原生操作，显示处理中并阻止同一实例的冲突重复操作。
4. 保留原生卸载确认、依赖/策略提示和重启要求；更新跟随原生网络/渠道/兼容行为，不擅自改自动更新设置。
5. 从原生状态重新读取结果后同步 TreeView 与 Dashboard；需要重启时显示待生效，不能假报立即生效。
6. 取消、权限失败、网络失败保持可解释的现状并提供重试；不清除分组。

侧边栏聚合行发起管理时：单实例可直接定位；多实例先弹出可用鼠标点击的目标列表，列出 Local/Remote、版本和状态，再选择全局或 Workspace 范围。取消任一步均不执行动作。Dashboard 已选定实例时沿用该目标；仅选中聚合行时使用相同目标选择流程。

### 7.3 已核对与待验证

官方文档列出了 workbench.extensions.installExtension、workbench.extensions.uninstallExtension 和 workbench.extensions.search。[Built-in Commands](https://code.visualstudio.com/api/references/commands)

原生扩展页支持包含禁用插件的已安装列表，以及启停、更新和卸载；本产品复用这些原生流程。[Extension Marketplace](https://code.visualstudio.com/docs/configure/extensions/extension-marketplace)

公开 Extension 对象的 isActive 代表已激活，不能当成 enabled；标准类型中没有可直接使用的统一 enable/disable 成对方法。完整清单、真实启用状态与更新可用性仍需 M0 实测数据通路。[VS Code 类型定义](https://github.com/microsoft/vscode/blob/main/src/vscode-dts/vscode.d.ts)

CLI 公开提供清单、版本、安装/更新与卸载能力，但不能由此假设获得完整的启用状态或正确 Remote 目标。[Command Line Interface](https://code.visualstudio.com/docs/configure/command-line)

以上是文档核对，不是运行验证，也不是“一套 Marketplace 接口已经全部可用”的结论。

## 8. 数据模型与导入导出

项目还没有已发布持久数据，直接采用唯一归属 schemaVersion=1；这是数据格式标识，不是产品版本更新。

```json
{
  "schemaVersion": 1,
  "groups": [
    { "id": "g-python", "name": "Python & Data", "order": 0 },
    { "id": "g-research", "name": "Research", "order": 1 }
  ],
  "assignments": {
    "ms-python.python": "g-python",
    "ms-toolsai.jupyter": "g-research"
  }
}
```

- assignments 的值只能是一个有效 Group ID，缺少 key 表示 Ungrouped；数组形式非法。
- Group ID 稳定；Extension ID 大小写规范化后唯一，大小写冲突不能静默覆盖。
- 严格识别重复 JSON key、重复 Group ID、重复组名、无效引用、非法类型和 ID；不能依赖解析器保留最后值来掩盖冲突。
- order 为非负整数；重复顺序以数组顺序稳定排序并规范化。动态版本、启用状态和更新结果不作为分组配置导出，导入不能触发启停或安装。
- 运行态以 Extension ID + 安装目标区分实例，记录版本、真实启用状态/原因、更新状态及 freshness；多个实例共享同一分组归属。

导入顺序：选择文件 → 完整校验 → 显示组数/归属数/尚未安装数 → 提供先导出备份入口 → 确认整体替换 → 一次性持久化。单组文件也明确是替换而非合并；合并留待 P1。取消、校验或保存失败不改原有效状态。单组导出仅含选中组及其 assignments。

初稿 memberships 数组格式尚未投入使用，不承诺兼容；若用户导入旧草案格式，说明不支持并要求显式转换。不得自动挑选多归属中的第一个组造成无提示的数据损失。

首选 globalState，key 建议 extensionNest.state；Profile/Remote 隔离与多窗口并发需实测。不承诺跨机器同步。读取失败保留原始数据，提供重试/恢复入口；不生成空状态覆盖。更新、禁用不改变归属；确认卸载后可保留归属供同 ID 重装恢复。

## 9. 技术路线与质量

建议 TypeScript 扩展宿主 + 原生 TreeView + 编辑器 Webview Dashboard。Dashboard 可采用 React（TypeScript）+ Vite，在 VS Code 内运行，不另设 Web 后端。这里解除初稿对正式 Webview 的全面排除；原生侧边栏仍保留。

models 定义唯一归属与安装实例；services 提供分组/安装清单/状态同步/导入导出；adapters 封装原生管理；views 提供树；dashboard 提供概览和列表。两种 UI 只发送经过校验的动作，不直接写持久化或执行任意命令。

| 类别 | 要求 |
| --- | --- |
| 性能 | 100 个唯一 ID、最多 150 个安装实例、20 个组、最多 100 个 assignments；预热展开数据准备 p95<100 ms（30 次）；分组操作反馈目标<200 ms；本地快照就绪后 Dashboard 首屏目标<1 s；网络管理耗时单独呈现 |
| 同步 | 管理操作/原生变更后自动同步；收到可用状态通知后两种视图更新目标<2 s；漏事件需在面板重新聚焦及手动刷新时重读；后台更新状态也需验证 |
| 鼠标 | 核心整理和管理流程不依赖快捷键；拖放有目标提示；灰色禁用行仍可操作；名称和搜索可以输入文本 |
| 主题 | Light/Dark/High Contrast，清晰 Disabled/Unknown/Mixed/Restart Required 标识，保持文本对比度 |
| 数据 | 分组操作和安装操作分离；失败不部分保存；不主动激活其他扩展；保留最后有效清单并标注过期 |
| Webview | 限制脚本与资源来源；消息白名单并校验 ID/目标/操作；显示名与描述按文本渲染，不执行导入内容 |
| 平台 | Windows 优先；发布前验证 macOS/Linux 和 WSL/SSH 当前连接场景；未测试平台不得宣称已通过 |
