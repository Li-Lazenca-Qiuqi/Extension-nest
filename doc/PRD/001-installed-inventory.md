## 1. 目标与需求

| 编号 | 功能 | 必须满足的行为 |
| --- | --- | --- |
| F01 | 全量安装清单 | 对当前管理范围建立完整已安装清单，与原生安装清单逐 ID/目标比对；包含禁用、未激活、VSIX、无 Marketplace 条目的安装；内置扩展提供独立可选过滤但不遗漏；缺少元数据时仍以 ID 占位 |

## 2. 规则与交互

以当前 Profile、本地和当前已连接 Remote 为范围，按 Extension ID + 安装目标核对原生清单。界面显示当前范围。已安装但缺少图标、描述或 Marketplace 条目时，仍以 ID 占位；初次清单不完整不能通过验收。

“全部已安装可见”是验收要求，不能以 vscode.extensions.all 的返回值重新定义。原生 Marketplace 中没有条目、图标或描述时，已安装记录仍显示 ID 和可用信息。禁用不能成为隐藏理由。

当前 Profile、Local 与已连接 Remote 的默认范围是本稿工作解释；不自动连接其他主机。按同一范围与原生清单对照，原生内置扩展也须在明确过滤入口中可查看。切换 Profile 后重新读取该 Profile 的安装集，不混入旧目标；分类持久化的隔离策略在 M0 记录。

本稿所有“完整/全部”及验收数据均以上述当前管理范围为边界，而非所有设备和所有 Profile 的并集。Dashboard 持续显示此范围，验收记录同时写明 Profile 和连接目标；在这个范围内不允许漏掉任何已安装实例。

连接中断或同步失败保留上次清单并标记 Stale/Offline，不清空为“已卸载”，不显示“同步完成”。初次读取不完整时提示清单不完整并给重试入口；未补齐前不能判定 F01 完成。
