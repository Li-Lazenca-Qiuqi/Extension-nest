## 1. 目标与需求

F15：单一宿主发现/组织状态源驱动两视图，只同步公开可见性与组织元数据，不承诺完整原生安装/启停/更新事件。

## 2. 规则与交互

启动、extensions.onDidChange、窗口聚焦、Dashboard 再次可见/激活和手动 Refresh 触发合并去抖重读。事件仅为失效提示；同窗口切回标签不一定触发窗口 focus，需单独覆盖。不轮询启停或更新，不通过多刷 registry 宣称完整清单。

每轮捕获上下文 generation 和请求序号；过时结果、取消结果不能覆盖新轮次。Profile 切换后重新载入其存储，清空当前投影后加载新上下文，不对旧 Profile 执行缺失判定。切换离开再回来也要丢弃旧请求，不仅比较 ID。失败保留旧缓存标 Stale，不更新 lastSeenAt，不降为 NotVisible。

成功读取、合并发现缓存并保存后，原子发布同一份树与 Dashboard 快照。缓存写失败不发布虚假的持久化成功，保留上次有效快照及重试；组织事务独立，不被发现覆盖。可用通知后视图更新目标<2 s，漏事件通过面板/聚焦/手动补读恢复，但不推断缺失原因。

多窗口必须防丢写：实现单写者协调或实际事务方案，在完成前不能开放未经保护的并发写入。globalState 不提供公开 CAS，分 key、revision 或单宿主队列都不等于跨窗口锁。当前采用应用存储目录级单写者租约，Windows 使用命名管道；此目录仅定义锁域，不充当 Profile ID。只读窗口不写组织或发现缓存，当次发现只在内存保留。租约在宿主退出且队列结束后释放，只读窗口需重新加载才能竞争写入权。跨进程互斥已有测试，真实双窗口 UI 与存储传播仍待验收。

## 5. 当前实现边界

宿主队列串行化读取与组织动作，事件去抖；异步保存之后检查宿主是否已释放，再发布状态。当前上下文边界是 Extension Host 实例生命周期，尚未以公开 API 识别实时原生 Profile ID。隔离宿主验证了不同启动 Profile；运行中切 Profile/切回仍列为待验收，不能声称 generation 全场景已完成。
